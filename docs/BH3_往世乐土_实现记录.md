### 2.2 Scripted GUI

- 效果：每个按钮都有 _click，内部都有 if 守卫（层数/钥匙/是否已用过），防止显隐触发器失效时误扣。
- 触发器：_visible 控制出现条件，_enabled 控制钥匙是否足够。
- 入口：主菜单 ER 按钮点击时同时置 BH3_main_menu_open，保证父窗口存在。

### 2.3 已知风险

- 若 _visible 触发器在某些版本不生效，按钮会常显但点击被守卫拦下（不会误操作）。
- 背景是 PNG sprite（本 mod 已验证可行）；如某版本不吃 PNG，可改用同名 dds。


### 2.4 右上角层数提示（2026-11-25 追加）

- 位置：ER 窗口右上角（x=960, y=18，右对齐），显示“第 N / 17 层（层类型）”

- 旧的左侧 BH3_ER_floor_text（defined_text）已移除，避免两处显示不一致

## 3. 刻印获取机制（2026-11-25 第一版）

### 3.1 文件位置（2026-11-25 实测修正）

**HOI4 1.19 不加载 common/scripted_effects 的子目录**——已实测：放在子目录里的效果全部报 Unknown effect-type。

因此刻印文件直接放在 common/scripted_effects/ 根目录，用统一前缀区分：

- 命名约定：BH3_ER_signets_<系名或编号>.txt（将来 12 系 = 12 个文件）
- 当前：BH3_ER_signets_00_test_pool.txt（6 个测试刻印 + 抽取/放弃/授予效果）
- 子目录方案作废，不要再新建 BH3_ER_signets/ 这类目录放脚本

### 3.2 变量

| 变量 | 含义 |
|---|---|
| BH3_ER_draws | 剩余抽取次数（每推进一层 +1，双倍层购买再 +1） |
| BH3_ER_offer | 1 = 当前正在展示候选 |
| BH3_ER_c1 / c2 / c3 | 三枚候选的刻印 ID（0 = 空） |
| BH3_ER_signets | 已获得刻印数（成就/统计用） |

### 3.3 流程

1. 进入新一层 → BH3_ER_draws +1
2. 点「抽取刻印」→ BH3_ER_roll_offer：扣 1 次抽取，随机掷出 3 个不同候选（1~6），置 offer = 1
3. 6 个候选按钮按 c1/c2/c3 的取值显示（每个按钮 _visible 判断自己是否在候选中）
4. 点候选 → BH3_ER_signet_grant_N：给对应国家精神（已有则跳过）、刻印数 +1、清空候选
5. 点「放弃本次抽取」→ 退还抽取次数并清空候选

## 5. 映射口径统一（2026-11-25 晚）

**所有“穿透 / 无视防御 / 降低抗性”类词条统一映射为两个独立词条：**

- army_attack_against_major_factor（对主要国家的攻击）
- army_attack_against_minor_factor（对次要国家的攻击）

两者都按原数值给满（视为独立加成）。据此回改救世：

| 刻印 | 原映射 | 新映射 |
|---|---|---|
| 104 猎杀者的假面（物理穿透 35%） | breakthrough +35% | 对主要/次要国家攻击各 +35% |

**易伤乘区（敌人受到的全伤害提高）统一映射为“特种攻击”：**

## 6. 第二组刻印：黄金（Gold，2026-11-25 第二版）

### 6.1 设计（政治点 = 能量）

- **普通刻印**：按**当前政治点数**给动态修正。引擎用 has_political_power 触发器读取（每 25 点一档，on_daily 更新档位），档位 × 25 作为近似政治点，再换算成各类加成。
- **核心Ⅰ 咏叹**：按**累计回复量**工作。每日用档位变化累计回复的政治点；累计每满 100 点触发一次【咏叹的雷鸣】，给予 3 天的限时加成（对主要/次要国家攻击各 +20%，代表雷鸣+沉醉）。
- **核心Ⅱ 余音**：按**累计消耗量**工作。每日用档位下降累计消耗的政治点；拥有核心Ⅱ时，终末余音增伤 = 累计消耗 × 0.2%（上限 +160%），直接并入全伤害。
- 全系仍只有 1 个动态修正 BH3_ER_dm_gold，5 个输出变量由 recalc 每日重算。

### 6.2 变量

| 变量 | 含义 |
|---|---|
| BH3_ER_gold_bucket / _prev | 当前/上次政治点档位（25 点一档） |

### 9.6 投降度 = 生命值（全局约定，2026-11-26）

引擎没有“部队被击中”的触发器，但 surrender_progress 会随战线恶化上升，正好可以当生命值：

- 每天用 has 阈值把 surrender_progress 分档（每 5% 一档，0~20 档），记录 BH3_ER_surr_tier
- BH3_ER_surr_delta = 今天上升的档数；>0 即判定“受击”
- BH3_ER_surr_hp = 100 - 5 乘档位（0 = 满血，100 = 濒临投降）
- 浮生：delta>0 时消耗 1 层（单日最多 3 次判定）
- 将来的鏖灭：直接用 BH3_ER_surr_hp 做“低生命”条件（例如 hp < 50 触发燃血）

变量：BH3_ER_surr_tier / _prev / _delta / _hp（均在 init_run 初始化）。
调试：调试组「重算投降度并判定受击」「投降度写入日志」（BH3SURR 标记）。

### 9.7 核心机制验证（2026-11-26，2026-11-26 21:05 修正）

- 指挥官技能「浮生：无敌」正常出现在将领技能栏
- 该技能对**陆战伤害**有效（str/org_damage_multiplier = -1.0）
- **修正**：之前记录“用核导弹袭击测试、袭击重大失败”是误判——那次重测后袭击正常生效，第一次的“重大失败”属于单次随机结果
- 结论：unit_modifiers 的 -1.0 只覆盖陆战伤害，**不影响核袭击/战略打击这类特殊攻击**；测试单一随机事件必须重复多次才能下结论

### 9.8 无敌改为可储存次数（2026-11-26 第三版：两组核心都有无敌）

问题：原本“抵消后给 2 天无敌窗口”要求玩家在窗口内立刻用技能，而玩家通常不会盯着投降倾向变化。

最终规则：
- 每次抵消伤害（无论核心Ⅰ的【战士的决意】还是核心Ⅱ的【战士的回忆】）→ BH3_ER_fs_charges +1（抵消本次伤害本身等价于短暂无敌）
- **移除自然消耗**：存的次数不会自动减少，只有使用技能才消耗（技能 cooldown 1 天，每天最多用 1 次）
- **存储上限由核心决定**：BH3_ER_fs_charge_cap 默认 3（核心Ⅰ可用）；核心II（411）授予时设为 6；413 如羽随风再 +3（上限 9）
- 413 不再按每次抵消延长无敌时间，改为直接提高存储上限（对应“浮生系时间不再延长”的调整）
- 技能 allowed = charges > 0


### 9.9 无敌拦截袭击（已回滚，暂缓）

尝试过两版实现，均未生效，已回滚到“只有指挥官技能”的版本：

1. 技能 one_time_effect 置旗标 → 测试 mod 验证**可以生效**（旗标能设置）
2. 用 raid 的 success_factors 自定义成功率修正（formula + weight -1.0/-5.0）让“目标国带旗标 → 袭击必失败” → 测试了 actor / target / FROM 三种作用域共 6 组，**全部不生效**

结论与待办：
- raid 的成功率公式可能不接受 has_country_flag 这类布尔触发器，或自定义修正的覆盖方式有问题
- 后续若继续做，可尝试：数值变量方案（scope = country + factor = 变量）、或在 raid_definition 层面新建“反制型袭击”而非修改成功率
- on_nuke_drop 钩子确认存在（写在 on_actions = { } 内才生效），可继续用于“拦截后扣费”
- 相关实验脚本保留在 tools/BH3_modtest 中（实验E：三种作用域变体）

**安全余量说明（重要）**：投降倾向不随占领领土线性变化（丢首都、丢关键 VP 会跳档），所以：

- 所有“低生命”条件都用**宽档位**判断（lost > 20 / 30 / 50），不做精确百分比依赖
- 单日受击/生命下降最多按 3 档处理，避免一次跳档把层数/充能清空
- 数值上限都做了 clamp，档位异常时不会爆炸

### 10.6 燃血代价与压血（自身投降倾向 debuff + 保护）

原作里“消耗自身血量”“生命无法超过 18%”在 HOI4 用**给自己上投降倾向 debuff** 实现：

- 新增国家精神「鏖灭：燃血代价」BH3_ER_az_bloodloss：**surrender_limit = -0.05**（投降界限降低 = 更易投降，方向与原版法国「混乱的政府」一致）、stability_factor -0.01
- 510 燃血解放释放时：附加 30 天「燃血代价」
- 511 压血：每天刷新 7 天「燃血代价」；同时把 BH3_ER_az_lost 强制抬到 ≥82（等价生命 ≤18%）

**保护（因为投降倾向不线性，不能放任自压）**：
1. 只有 surrender_progress < 25% 时才施加/刷新 debuff
2. surrender_progress > 50% 时立刻 remove_ideas 移除 debuff（安全阀）
3. debuff 数值很小（surrender_limit -0.05）且是限时精神，最多叠加一层
4. 其余低生命判定不受影响，可按 lost 连续计算（501/502/503/509 都是线性换算）

### 18.6 悬停提示修复（2026-11-27 三次，依据 error.log）

- Scoped text used in instant text box ... but no scoped localizer found
  → GUI 的 context_aware_text 里写 [定义名] 不成立；它要的是“作用域本地化器”，不是 defined_text
- Trying to do scoped tooltip localization on GUI type BH3_ER_slot_N_btn ... that doesn't support it
