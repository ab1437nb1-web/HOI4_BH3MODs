# 往事乐土 P3 方案：「真我」刻印（定制刻印位）

> 原则：**真我 = 每个国家独有的定制刻印**（原作里没有统一形态），所以做成
> **①8 个原版主要国家的预设**（仅历史线）+ **②一套开放接口**供 submod 定义各自国家的真我。

---

## 一、机制选型：用原版「任务」实现

已查证：原版意大利历史线「墨索里尼的任务」**不是** `timed_activities`，而是**决策的特殊形态**，定义在 `common/decisions/ITA.txt`，专属字段如下（原版多国在用：AFG/ARG/AST/ITA…）：

| 字段 | 作用 |
|---|---|
| `selectable_mission = yes` | 标记为"任务"（不是普通决议） |
| `available = { ... }` | **完成目标**：达成即完成 |
| `days_mission_timeout = N` | 时限（天）；超时进入 `timeout_effect` |
| `complete_effect` / `timeout_effect` / `cancel_effect` | 三种结算 |
| `is_good = yes` | 界面表现为"正面任务" |
| `highlight_states` / `cancel_if_not_visible` | 地图高亮 / 不可见即取消 |
| 配套 | 效果 `activate_mission`；触发器 `has_active_mission`；效果 `add_days_mission_timeout`、`remove_mission` |

**为什么选它**：① 原版机制、写法已验证；② 天然支持"**有时限、有成败**"的任务感；③ 任务的完成/失败都能挂效果，正好用来"**攒刻印**"。

**真我刻印的载体**（与其它刻印一致）：1 个民族精神（持有标记 + 图标）+ 1 个动态修正（真加成）。
真我**不计入 12 系列**（用户已明确），因此不参与"集齐 60 枚"的判定，也不受抽取池影响。

## 二、通用框架（所有国家共用）

### 2.1 每个国家的真我结构

```
（国家）真我任务链
   ├─ 任务 1：历史线早期目标  → complete_effect：给"真我·序"标记（+ 小效果）
   ├─ 任务 2：历史线中期目标  → complete_effect：给"真我·承"标记
   └─ 任务 3：历史线关键目标  → complete_effect：授予真我刻印本体（精神 + 动态修正）
```

- **任务失败不清零**：超时只给"警告性代价"（政治点/稳定度小幅损失），任务可重来（`fire_only_once = no` + 重新可用），避免挫败感；
- **真我刻印一次性授予**：拿到后永久保留，不因后续任务失败而收回；
- 三条任务都用 `cancel_if_not_visible = yes`，国家转向非历史线时自动取消。

### 2.2 开放接口（供 submod 定义自己的真我）

submod 只需按约定新增 3 个东西，**不需要改本 mod 任何文件**：

| 约定 | 内容 | 命名规则 |
|---|---|---|
| 精神 | 该国的真我刻印（持有标记 + 图标） | `BH3_ER_Elysia_<TAG>` |
| 动态修正 | 真加成分档（可选，可只给精神） | `BH3_ER_Elysia_<TAG>_dm` |
| 任务 | 该国的真我任务链 | `BH3_ER_Elysia_<TAG>_mission_N` |

并复用本 mod 提供的**公共脚本**（submod 直接调用，不必自己写）：

| 类型 | 名称 | 作用 |
|---|---|---|
| 脚本效果 | `BH3_ER_elysia_grant` | 授予某国真我刻印（自动判断精神/动态修正是否存在，缺哪个跳过哪个，不报错） |
| 脚本效果 | `BH3_ER_elysia_mission_ok` / `_fail` | 任务成功/失败的通用结算（提示、政治点、日志） |
| 脚本触发器 | `BH3_ER_has_elysia` | 判断该国是否已持有真我刻印（供其它系统联动） |
| 图标约定 | `gfx/interface/elysianrealm/signet_Elysia_<TAG>.png`（60×68，白色透明） | 未提供则用默认「真我」莲花图标 |

**文档**：`docs/BH3_ElysianRealm_P3_真我刻印_submod接口.md`（给 submod 作者的完整示例与字段说明）。

## 六、超时惩罚机制：照搬梅福券（已读原版实现）

原版 `GER_mefo_bills_mission` 的完整脉络：

1. 任务型决策：`days_mission_timeout = 180`、`is_good = yes`、`cancel_trigger = { ... }`；
2. 超时 `timeout_effect` 里：
   - `add_to_variable = { GER_mefo_bill_counter = 10 }`（**累积拖延计数**，并带"低于 15 就重置为 10"的下限保护）；
   - `set_variable = { GER_extend_mefo_bills_days = days_mission_timeout@GER_mefo_bills_mission }` → 配合 `days_remove = GER_extend_mefo_bills_days?0`，**把下一次时限延长**（用了 `days_mission_timeout@<任务id>` 读任务自身字段的写法）；
   - `activate_mission = GER_mefo_bills_mission` → **任务重新激活**，可以继续拖；
3. 惩罚由一个**变量驱动的动态修正**承载（`consumer_goods_factor = GER_industrial_consumer_goods_factor` 等，**直接写变量名**）。

### 我们的超时规则（决定）

| 项目 | 规则 |
|---|---|
| 时限 | 每阶段任务给 **N 天**（拟 180 / 240 / 300，逐阶段放宽） |
| 超时 | 记录 `BH3_ER_<TAG>_delay` 计数（+1），**任务重新激活**，可再来一次 |
| 惩罚 | 每个"拖延计数"给一份累积惩罚（动态修正读变量）：消费品 +2%、政治点 −5%、稳定度 −1%（拟） |
| 上限 | 计数上限 5 层（再拖不再叠加，避免无法挽回） |
| 成功 | 任务完成即**清除该阶段的拖延计数**（不带到下一阶段），并授予阶段奖励 |
| 失去 | **只有国家被彻底消灭（被吞并/投降后亡国）才移除真我**；其余情况永久保留 |
