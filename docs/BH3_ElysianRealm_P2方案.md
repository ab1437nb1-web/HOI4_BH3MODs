# 往事乐土 P2 方案（待你修改后再实施）

范围：其余 **11 派系**（救世已在 P1 完成）共 **55 项**（每派系 3 普通 + 核心 + 增幅）+ 跨派系抽签 + 重置。

---

## 一、一条必须先说清的引擎限制（影响"状态条件"的设计）

P1 的设想是"每个派系用各自的状态"（鏖灭=组织度低、浮生=组织度高、旭光=夜间）。**动态修正的 `enable` 只接受"国家层面"的触发器**，所以：

| 想用的状态 | 能否作为开关 | 处理方式 |
|---|---|---|
| 开战 / 停战 | ✓ `has_war` | 直接做开关 |
| 威胁度高 | ✓ `threat > 0.5`（mod 已在用 `threat > 0.4`） | 直接做开关 |
| 战争支持度 / 稳定度 | ✓ `war_support` / `stability` | 直接做开关 |
| **部队组织度**（鏖灭/浮生） | ✗ 引擎只在"国家"层判定 | 改为**效果本身**体现（组织结构、回复、强度、损耗） |
| **夜间**（旭光） | ✗ 同上 | 改为效果（`land_night_attack`、`air_night_penalty`） |
| 和平期（空梦） | ✓ `has_war = no` | 直接做开关（与其它派系互为镜像，主题感好） |

下文所有"状态"列都已按这条限制改写。

## 三、抽签机制（二选一，我建议 A）

### 方案 A（基线：盲抽，代码量小）
抽取决议 → 事件保留**固定选项**，但每个选项内部用 `random_list` 在"符合条件的派系池"里随机：

| 选项 | 条件 | 效果 |
|---|---|---|
| 抽一枚**普通刻印** | 有钥匙 | 在所有"普通未满 3 枚"的派系中随机 1 个，授予其下一级普通刻印 |
| 抽一枚**核心刻印** | 有钥匙 | 在所有"普通已满 3 枚且无核心"的派系中随机 1 个 |
| 抽一枚**增幅刻印** | 有钥匙 | 在所有"已有核心且无增幅"的派系中随机 1 个 |
| 放弃本次 | 恒可 | +25 政治点（防"无选项"卡死） |

### 方案 B（进阶：真·三选一，代码量约 2 倍）
抽取决议先**预抽 3 个候选**写入临时变量 → 用**脚本本地化**在选项文本里显示"你将获得：X / Y / Z" → 选哪个就套用哪个（12 派系 × 3 选项的 `if` 分支）。更接近原作手感，但需要新增脚本本地化块与更多调试。

## 八、追加设计②：天慧（情报机构 + 「陷阱提案」）

### 参考对象：workshop mod `3228475937` 的「陷阱提案」

该 mod 的做法（已读其文件）：**对他国发起"陷阱提案"**——文案明写"被我们策反的将领在当地情报网协同下提出新提案，看似拨款给后勤，实则将资金转入地下情报网"，即**用情报网在目标国制造一个假提案来拖累对方**。它走的是"决议 + 事件"路线。

HOI4 里更贴合的**原生载体是"情报机构行动"**（`common/operations/*.txt`），字段齐备：

| 字段 | 用途 | 原版示例值 |
|---|---|---|
| `days` / `network_strength` / `operatives` | 时长 / 所需情报网强度 / 特工数 | 35 / 30 / 1 |
| `visible` / `allowed` | 何时可见 / 可用（**可写 `ROOT = { has_idea = BH3_ER_Bodhi_Core }` 实现"由刻印解锁"**） | — |
| `risk_chance` / `outcome_extra_chance` | 暴露风险 / 额外结果概率 | 0.1 |
| `outcome_execute` | **成功后执行的效果**（作用域 OPERATION，可操作 ROOT/FROM） | `ROOT = { free_random_operative = { ... } }` |
| `outcome_potential` | 界面上"可能结果"的预览 | — |
| `phases` / `requirements` / `target_type` | 阶段 / 前置 / 目标类型 | — |

### 实施方案

1. **新建行动** `common/operations/BH3_ElysianRealm_operations.txt`
   ```
   BH3_ER_Bodhi_TrapProposal = {
       icon = GFX_operations_...（暂用原版图标占位）
       map_icon = ...
       name = BH3_ER_Bodhi_TrapProposal
       desc = BH3_ER_Bodhi_TrapProposal_desc
       days = 60
       network_strength = 40
       operatives = 1
       risk_chance = 0.15
       visible = { ROOT = { has_idea = BH3_ER_Bodhi_Core } }   # 核心刻印解锁
       target_type = country
       outcome_execute = {
           FROM = { add_dynamic_modifier = { modifier = BH3_ER_Bodhi_TrapDebuff } }   # 给目标挂"被拖累"的动态修正
       }
       outcome_potential = { FROM = { ...同上的预览... } }
   }
   ```
2. **新建减益动态修正** `BH3_ER_Bodhi_TrapDebuff`（写进现有 `BH3_ElysianRealm_dynamic_modifiers.txt`）

- `level = N` 字段的用途是"法律式递增花费"，**不是**把多条精神合并成一条显示。引擎**没有**"多条国家精神合并为一个条目"的原生写法。

**实现（可验证的部分全做了）**：

1. 新建 `interface/BH3_ElysianRealm_idea_icons.gfx`，定义 **12 个 `GFX_idea_BH3_ER_<英杰>` 精灵**，各自复用 mod 现有素材的图片：

2. 60 个精神全部写入 `picture = BH3_ER_<英杰>`（**同一英杰 5 枚共用同一图标**），名字前缀相同（「刹那·Ⅰ」…「刹那·增幅刻印」）→ 在政治界面的精神栏里天然**紧挨在一起**。

**仍未做到的（如需请告知）**：引擎不支持把 5 条精神合并为**单一**条目。若要"字面意义上一条"，可行方案是：5 条改为 `hidden_ideas`（隐藏但作为持有标记）+ 每个英杰 1 条摘要精神，用 `swap_ideas`（Wiki 已确认存在）随进度替换摘要的等级。代价是精神总数再翻倍、逻辑更绕，收益只是少 4 行显示。

## 实施记录（2026-10-08）

### 一、P2 审计与修复

对照本方案对实际 mod 做了全量审计，结论与处置如下：

1. **抽取事件普通刻印选项 trigger 缺前缀（bug，已修复）**
   `events/BH3_ElysianRealm_event.txt` 中 12 处普通刻印选项的 `trigger` 写成 `has_country_flag = ElysianRealm_...`，少了 `BH3_ER_` 前缀，导致已抽取过的刻印仍可被重复抽取。已全部补上前缀。
2. **「陷阱提案」情报行动（P3 待办第 2 项，已提前落地）**
   新建 `common/operations/BH3_ElysianRealm_operations.txt`：照原版 `operation_fake_intel` 的语法实现国家级目标行动（国家级目标**不声明** `target_type`）；60 天 / 需要情报网 40 / 1 名特工 / 风险 0.15；阶段名沿用原版渗透链（`infiltration_diplomatic`、`steal_blueprints_middle_manager`、`exfiltration_go_to_ground` 等）。成功时给目标国（FROM）挂 `BH3_ER_Bodhi_TrapDebuff` 120 天。
   配套：`common/dynamic_modifiers/BH3_ElysianRealm_dynamic_modifiers.txt` 追加 `BH3_ER_Bodhi_TrapDebuff`（`planning_speed = -0.30`、`army_attack_factor = -0.15`、`war_support_weekly = -0.05`，icon/enable 齐全）；本地化并入现有 `BH3_equipment_l_simp_chinese.yml` / `BH3_equipment_l_english.yml`（**未**新建独立 loc 文件——P1 已记录独立 loc 会装载崩溃）。
3. **天慧核心新增机制「拦截外国来源事件」（经验证不可实现，未做改动）**
   设想：所有触发来源不为本国、且带对玩家效果的事件，需玩家复核后才生效，否则拦截。核实 HOI4 事件系统后确认**无法实现**：事件由效果直接触发，选项效果立即执行，脚本层没有任何"事件拦截/否决"钩子；`on_actions` 只挂在游戏固定场合（如 `on_startup`、`on_capitulation`）上，无法包装或替换他人发起的事件。按约定还原（未做任何文件改动）。反间谍效果改由上述「陷阱提案」行动承担。
